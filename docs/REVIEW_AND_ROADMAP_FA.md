### ۱.۲ شکاف‌های بحرانی نسبت به سند (به ترتیب خطر)

1. **موتور گردش کار (State Machine) اصلاً وجود ندارد** — قلب محصول (§5) پیاده‌سازی نشده: نه اجرای تست، نه ثبت PASS/FAIL/BLOCKED، نه رفع خطا و Retest، نه تأیید/رد مدیر. جدول‌ها (`workflow_history`, `test_executions`, ...) آماده‌اند اما هیچ کدی به آنها نمی‌نویسد.
2. **عدم اعمال کنترل دسترسی** — هر کاربر لاگین‌شده به همه پروژه‌ها/سناریوها/خطاهای همه کاربران دسترسی دارد (نقض §3.2 و AT-02/AT-08). عضویت پروژه (`project_members`) خوانده نمی‌شود؛ IDOR باز است.
3. **انتساب سه مسئول پیاده نشده** — `test_assignments` خالی است؛ سناریو بدون مسئول فعال می‌شود (نقض §4.4 و AT-05).
4. **مراحل سناریو و Revision ندارد** — `test_case_steps` و `test_case_revisions` بلااستفاده‌اند؛ snapshot در اجرا ذخیره نمی‌شود.
5. **Import/Export اکسل کاملاً غایب** (فصل ۷) به‌همراه `templates/` و PhpSpreadsheet.
6. **اعلان‌ها، پیوست‌ها، Audit، گزارش‌ها، تنظیمات** — همه فقط جدول دارند؛ هیچ منطق/ UI‌ای ندارند.
7. **سخت‌سازی احراز هویت ناقص** — بدون rate-limit، بدون اجرای `must_change_password`، بدون صفحه تغییر رمز، بدون `last_login_at`، بدون timeout فعالیت.
8. **معماری** — کنترلرها query زنده دارند؛ لایه Service (§11) وجود ندارد؛ auth با `if(!session(...))` تکراری در هر متد به‌جای Route Filter؛ صفحه‌بندی/فیلتر/جست‌وجو در هیچ لیستی نیست (نقض §1.4)؛ تاریخ جلالی ندارد.
9. **FK های دیتابیس** — جداول عملیاتی با SQL خام و بدون FOREIGN KEY واقعی ساخته شده‌اند؛ یکتایی‌ها هست اما integrity ارجاعی نه (باید در migration تکمیلی اضافه شود).
10. **لینک‌های مرده سایدبار** — گزارش‌ها/اعلان‌ها/تنظیمات به `#` اشاره می‌کنند.

### ۱.۳ جمع‌بندی

اسکلت و زیرساخت داده آماده و سالم است؛ اما **حدود ۷۰٪ ارزش محصول (گردش کار تست، کنترل نقش‌ها، Import/Export، گزارش)** هنوز ساخته نشده. پیشنهاد ادامه در بخش ۳ و ۴ همین سند است.

## بخش ۲ — معماری هدف

```
Controller (نازک: ورودی/خروجی)
   ↓
Route Filters:  auth → projectAccess → roleInProject
   ↓
Service Layer:
   WorkflowService      ماشین حالت §5 + تراکنش اتمیک + locking خوش‌بینانه (lock_version)
   AssignmentService    سه مسئول + اعتبارسنجی نقش در پروژه + تاریخچه Audit
   ImportExportService  XLSX/CSV با پیش‌نمایش و گزارش خطا
   ReportService        KPI بر اساس «آخرین Execution هر آیتم»
   AttachmentService    ذخیره خارج از public + MIME واقعی + دانلود مجاز
   NotificationService  اعلان درون‌برنامه‌ای + badge شمارنده
   AuditService         ثبت رخدادهای حساس
   ↓
Models (allowedFields + validation + soft-delete)
```

قواعد ثابت: هر تغییر وضعیت = یک تراکنش (execution + defect + workflow_history + notification + audit) یا rollback؛ سرور هیچ `to_status` خامی نمی‌پذیرد و فقط «رویداد» می‌گیرد (§12).

### ۴.۵ شرح صفحات کلیدی

1. **ورود** — الگوی فعلی (پنل برند + کارت ورود) نگه داشته شود؛ اضافه: نرخ محدودیت با پیام فارسی، انیمیشن ورود نرم.
2. **داشبورد** — ردیف ۴ کارت KPI (سناریوهای فعال / در اجرا / خطاهای باز / در انتظار تأیید من) + دو نمودار Chart.js (روند PASS-FAIL دو هفته، توزیع وضعیت دوره جاری) + «لیست اقدام‌های امروز من» با دکمه ورود مستقیم به صفحه اجرا.
3. **کارتابل** — سه تب + فیلتر پروژه/اولویت + ردیف‌های کارت‌مانند (نه جدول خشک): عنوان سناریو، پروژه/دوره، badge وضعیت، مسئولان (آواتار سه‌نفره)، دکمه اقدام اصلی متناسب نقش (شروع تست / ثبت نتیجه / اعلام رفع / تأیید).
4. **صفحه اجرای تست (مهم‌ترین صفحه)** — چیدمان دو‌ستونه: راست = چک‌لیست مراحل سناریو با دکمه «طبق انتظار/خلاف انتظار» هر مرحله + پیش‌نیازها و داده تست؛ چپ = فرم نتیجه (PASS/FAIL/BLOCKED)، شرح واقعی، آپلود شواهد (دراگ‌اند‌دراپ)، ایجاد سریع Defect؛ پایین = Timeline تاریخچه اجراها و وضعیت‌ها.
5. **سناریوها** — Grid + ویزارد ۳ مرحله‌ای ایجاد/ویرایش (اطلاعات ← مراحل ← مسئولان) با اعتبارسنجی مرحله‌ای؛ نمای جزئیات با تب‌های «مشخصات / مراحل / مسئولان / Revisions / اجراها».
6. **خطاها** — Grid با نوار فیلتر severity/status/برنامه‌نویس + Drawer جزئیات: توضیح، Steps، کامنت‌ها (چت‌مانند)، فرم اعلام رفع.
7. **گزارش‌ها** — نوار فیلتر پروژه/نسخه/دوره/بازه + کارت‌های KPI تعریف‌شده §9 + نمودارها + دکمه Export CSV/XLSX.

### ۴.۶ مسیر فنی پیاده‌سازی UI

- **بدون Node و بدون build** (الزام §2.2): CSS خالص با توکن‌های بالا در `public/assets/css/theme.css` + `app.css`؛ آیکن‌ها **Bootstrap Icons** محلی؛ نمودار **Chart.js** محلی؛ فونت **Vazirmatn** محلی.
- یک `layout/main.php` مشترک (سایدبار + topbar + ناحیه flash) که همه ویوها با `extend` استفاده کنند؛ سایدbard فعلی به این ساختار ارتقا یابد و لینک‌های مرده حذف شوند.
- `prototype.html` به‌عنوان مرجع بصری باقی بماند؛ تبدیل صفحات آن به ویوی واقعی در فازهای ۱ تا ۵ به‌تدریج.

## بخش ۵ — اقدامات انجام‌شده در این نشست

1. رمز کاربر `admin` به مقدار خواسته‌شده تغییر کرد (`must_change_password=0` گذاشته شد تا ورود بدون مانع باشد) و با `password_verify` تأیید شد.
2. `start.sh` ساخته شد: پیدا کردن PHP → بررسی/اجرای سرویس MariaDB → ساخت دیتابیس در صورت نبود → migration معلق → تضمین مدیر اولیه → توقف سرور کهنه → اجرای `spark serve` روی `0.0.0.0:3838` → سلامت‌سنجی HTTP → نمایش آدرس‌ها (localhost + LAN) و بازکردن مرورگر. زیرفرمان‌های `stop`/`restart` و پورت دلخواه (`./start.sh run 8090`) دارد.
3. `start.bat` برای دابل‌کلیک ویندوز (فراخوانی Git Bash) اضافه شد.
4. `bin/ensure_ready.php` برای آماده‌سازی دیتابیس/مدیر اولیه به‌صورت idempotent اضافه شد.
5. `app.indexPage` در `.env` خالی شد تا URLها بدون `index.php` باشند.
6. تست واقعی HTTP انجام شد: لاگین موفق 303→داشبورد 200، همه ۶ صفحه 200، رمز غلط به لاگین برمی‌گردد؛ `INITIAL_ADMIN_PASSWORD` در `.env` (gitignore شده) برای bootstrap ثبت شد.
