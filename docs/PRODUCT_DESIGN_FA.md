# طراحی مرجع محصول

این سند، ترجمهٔ اجرایی SRS به تجربهٔ کاربری و ساختار ماژول‌هاست. هیچ صفحه‌ای نباید خارج از این ساختار طراحی شود.

## چارچوب ثابت

- سایدبار راست ثابت: داشبورد، کارتابل من، پروژه‌ها، سناریوها، دوره‌های تست، خطاها، گزارش‌ها، اعلان‌ها و بخش مدیریت (کاربران، تنظیمات).
- نوار بالای محتوا: Breadcrumb، جست‌وجوی سراسری، اعلان‌ها، نام کاربر و خروج.
- همهٔ صفحه‌ها در موبایل سایدبار کشویی و جدول‌ها دارای scroll افقی امن هستند.
- هر Grid: عنوان، شمارش رکورد، ایجاد مورد جدید، فیلترهای سمت سرور، جست‌وجو، صفحه‌بندی، ستون وضعیت رنگی و اکشن‌های مجاز نقش کاربر.
- همهٔ فرم‌ها: گروه‌بندی معنایی، راهنمای فیلد، اعتبارسنجی کنار فیلد، پیام فارسی و redirect-after-post.

## نقشهٔ جریان اصلی

1. مدیر پروژه را، اعضا و نقش‌های پروژه را ایجاد می‌کند.
2. مدیر درخت ماژول و نسخه را تعریف می‌کند.
3. مدیر سناریو، مراحل و سه مسئول مستقل را ثبت می‌کند؛ فقط پس از اعتبارسنجی به ACTIVE می‌رود.
4. مدیر سناریوهای ACTIVE را به Test Run باز اضافه می‌کند؛ هر مورد READY می‌شود.
5. آزمونگر از کارتابل نتیجه ثبت می‌کند: PASS به PENDING_APPROVAL، FAIL با Defect به IN_FIX و BLOCKED با دلیل به BLOCKED می‌رود.
6. توسعه‌دهنده رفع را ثبت می‌کند و مورد READY_RETEST می‌شود.
7. آزمونگر Retest می‌کند و مدیر نتیجه را تأیید، رد یا بازگشایی می‌کند.
8. هر انتقال همراه تاریخچه، اعلان و Audit است؛ هیچ اجرای تست یا وضعیت گذشته overwrite نمی‌شود.

## صفحه‌های الزامی

| صفحه | داده اصلی | اقدام‌ها |
|---|---|---|
| داشبورد | KPI واقعی پروژه/نقش | فیلتر پروژه و رفتن به کارتابل |
| کارتابل | Test Run Case بر اساس نقش | اجرای تست، رفع، تأیید |
| پروژه‌ها | Projects | CRUD، archive، اعضا، درخت، نسخه‌ها |
| سناریوها | Test Cases + revisions | CRUD، مراحل، انتساب سه مسئول، فعال‌سازی |
| دوره‌ها | Test Runs + cases | CRUD، افزودن سناریو، بستن دوره |
| خطاها | Defects + comments | ثبت، کامنت، شروع رفع، اعلام رفع، بازگشایی |
| کاربران | Users + global roles | ایجاد، فعال/غیرفعال‌سازی، جلوگیری از حذف آخرین Admin |
| گزارش‌ها | آخرین Execution هر آیتم | KPI، فیلتر و خروجی CSV/XLSX |

## قواعد غیرقابل‌تغییر

- مجوزها در Controller/Service و بر اساس نقش پروژه اعمال می‌شوند، نه در UI.
- `workflow_status` فقط متعلق به `test_run_cases` است؛ نتیجهٔ PASS/FAIL/BLOCKED وضعیت Workflow نیست.
- مسیرهای مستقیم کاربر غیرعضو باید 403 یا 404 امن بدهند.
- پیوست‌ها private، با MIME واقعی، کنترل حجم و دانلود احراز هویت‌شده هستند.
- داده‌های تاریخی soft-delete یا archive می‌شوند و حذف فیزیکی ندارند.

## معیار طراحی تکمیل‌شده

هر ماژول فقط وقتی تمام است که مسیر UI، migration، مدل، Service، authorization، تست پذیرش و مستندات آن کنار هم وجود داشته باشند.
